# S2 설계 — 시트 → IR

> 2026-07-29 작성. 개발가이드 §4 의 S2 세션에 해당합니다.
> 대상: `workbook-reader` · `header-parser` · `value-parser` · `build-ir`
> 성공 조건: `basic` 픽스처가 골든 IR 과 일치하고 `npm test` 가 통과한다.

이 문서는 사양(`spec.md` · `notation.md`)이 정하지 않은 구현 판단만 기록합니다.
사양과 겹치는 내용은 반복하지 않고 참조합니다.

---

## 0. 착수 전제

`spec.md` 머리말은 검토 전 초안이므로 구현을 시작하지 말라고 적고 있습니다.
S2 착수 시점에 **§3(입력 규약)과 §4(IR)를 확정으로 간주**하기로 했습니다.
§11.1(Newtonsoft 전제)은 §6 에미터에만 걸리는 결정이라 S2 를 막지 않습니다.

실제 데이터시트가 나와 IR 구조를 고쳐야 하면 `irVersion` 을 올리고 골든을 갱신합니다.
§4.1 이 정한 버전 올림 메커니즘이 정확히 이 용도입니다.

## 1. 사양에서 고칠 지점

S2 착수 전에 발견한 사양의 오류·미비입니다. 코드가 아니라 문서를 고칩니다.

### 1.1 enum 멤버 좌표의 시트명

`spec.md` §4 IR 예시가 enum 멤버 좌표를 `Grade!A4` 로 적었습니다. 원본 시트명은
`enum.Grade` 이므로 **`enum.Grade!A4`** 가 맞습니다. §5.1 이 요구하는 것은 사람이
시트에서 찾아갈 수 있는 좌표이고, `Grade` 라는 시트는 워크북에 존재하지 않습니다.

### 1.2 `long` 의 정밀도

`notation.md` §3 은 `long` 을 64비트라고만 적었습니다. JavaScript 의 `number` 는
2^53 까지만 정확하므로 `9007199254740993` 이 조용히 `9007199254740992` 가 됩니다.

`BigInt` 로 보관하면 `JSON.stringify` 가 던지고 골든 파일 비교가 깨집니다.
문자열로 보관하면 IR 소비자가 전부 재해석해야 합니다.

**결정: `Number.isSafeInteger` 범위 밖은 `E006` 으로 거부합니다.** 조용한 반올림은
이 도구의 존재 이유와 정면으로 충돌합니다. 실제로 막히는 사례(스노우플레이크 ID,
유닉스 밀리초)가 나오면 그때 문자열 보관을 도입합니다.

### 1.3 enum 정의 시트의 타입 행

`spec.md` §3.3 예시에 타입 행(`string` / `int?` / `string?`)이 있습니다. 그런데 이
스키마는 도구가 정하는 것이라 사용자가 바꿀 수 없습니다.

**결정: enum 정의 시트는 필드명 행에서 `name` · `value` · `comment` 열을 이름으로
찾고, 타입 행은 읽지 않습니다.** 열 순서도 고정하지 않습니다 — 이름으로 찾으므로
`comment` 가 앞에 있어도 동작합니다. §3.3 예시의 타입 행은 사람이 읽는 설명으로
남겨두되, 도구가 무시한다는 사실을 문서에 적습니다.

### 1.4 검증 코드의 세션 배치

개발가이드 §4 는 S3 를 "E001~E003" 으로 적었습니다. 그런데 이 코드들은 파싱 중에만
감지할 수 있습니다. `spec.md` §4.1 이 "`values` 는 캐스팅 완료 상태" 를 요구하므로
캐스팅이 S2 에 있고, 빈 `int` 셀을 만난 시점에 이미 E003 인 것을 압니다. 이를 S3 로
미루려면 타입 트리를 한 번 더 걸어야 합니다.

아래 §3 에서 경계를 다시 긋습니다.

## 2. 모듈 구성

```
src/core/
├─ util/a1.js            (시트명, 행번호, 열인덱스) → "Monster!D17"
├─ ir/
│  ├─ schema.js          IR_VERSION · 기본 레이아웃 · 무시 규칙 상수
│  └─ diagnostic.js      { code, cell, message, detail } 생성
└─ parser/
   ├─ workbook-reader.js SheetJS 유일 접점. 바이트 → { fileName, sheets }
   ├─ header-parser.js   2차원 배열 + layout → 필드 정의 + 진단
   ├─ value-parser.js    셀 문자열 + TypeNode → 값 + 진단
   └─ build-ir.js        위 셋을 2패스로 조립
```

`diagnostic.js` 를 `validate/` 가 아니라 `ir/` 에 둡니다. 진단은 IR 과 함께 이동하는
데이터이고, `parser/ → validate/` 라는 어색한 의존 방향을 만들지 않기 위해서입니다.
S3 의 `validate/report.js` 는 이 객체를 사람이 읽는 문자열로 **포맷팅만** 합니다.

### 2.1 각 모듈의 계약

**`util/a1.js`** — 다른 모듈을 import 하지 않습니다.

```js
columnLetter(columnIndex)                    // 0 → 'A', 26 → 'AA'
cellRef(sheetName, rowNumber, columnIndex)   // ('Monster', 17, 3) → 'Monster!D17'
sheetRef(sheetName)                          // 'Monster!'
```

행 번호는 엑셀 화면에 보이는 그대로 1부터 셉니다. 열 인덱스는 0부터입니다.
둘의 기준이 다른 것은 혼란스럽지만, 행은 사용자가 보는 값이고 열은 배열 인덱스라
각자의 문맥에서는 자연스럽습니다. 함수 하나로 감싸는 이유가 이것입니다 —
좌표 계산이 호출부마다 흩어지면 `Monster!D17` 이 어긋나기 시작합니다.

**`workbook-reader.js`** — SheetJS 를 아는 유일한 파일입니다.

```js
readWorkbook(data, { fileName }) → { fileName, sheets: [{ name, rows }] }
```

`rows` 는 2차원 문자열 배열입니다. 시트의 전체 범위(`!ref`)만큼 패딩해 열 인덱스가
A1 문자와 항상 일치하도록 합니다. 빈 셀은 `''` 입니다.

**`header-parser.js`**

```js
parseHeader(sheetName, rows, { layout }) → { fields, diagnostics }
```

`fields[]` = `{ name, column, columnLetter, type, comment, cell }`.
`type` 은 `type-notation.js` 가 낸 TypeNode 입니다.

**`value-parser.js`**

```js
parseValue(text, type, { cell, delimiter, resolveRef }) → { value, diagnostics }
```

`resolveRef(sheetName, fieldName)` 은 참조 대상 필드의 TypeNode 를 돌려주거나
`null` 을 돌려줍니다. 이 함수가 2패스 구조의 접점입니다.

**`build-ir.js`**

```js
buildIR(workbook, { layout, arrayDelimiter }) → { ir, diagnostics }
```

## 3. 진단 경계 — S2 와 S3 의 분담

```
S2 (파싱 중)  "이 값을 IR 에 넣을 수 없다"
   E001 필드명 중복·누락      E002 타입 표기 누락
   E003 필수 값 누락          E005 타입 표기 파싱 실패
   E006 값 캐스팅 실패        E008 ref·enum 대상 정의 없음
   E010 enum 정의 오류        E013 지원하지 않는 타입(배열 깊이 2+)

S3 이후 (IR 완성 후)  "IR 은 만들어졌는데 규칙 위반"
   E004 E007 E009 E011 E012 E014 E015 · W101~W106
```

경계의 기준은 **"IR 에 넣을 값을 정할 수 있는가"** 하나입니다.

- `E008` 이 S2 에 있는 이유: `ref:Item.id` 의 값을 캐스팅하려면 `Item.id` 의 타입을
  알아야 합니다. 대상이 없으면 캐스팅 자체를 못 합니다.
- `E010` 이 S2 에 있는 이유: enum 멤버의 값 자동 증가(생략 시 이전 + 1)를 S2 가
  계산하므로 값 중복이 그 자리에서 보입니다. 나눠 두면 같은 순회를 두 번 합니다.
- `E009`(멤버 없음)가 S3 인 이유: enum 값은 멤버 이름 문자열로 IR 에 들어가므로
  정의에 없어도 IR 은 만들어집니다.

S3 는 검증기 프레임워크 · 리포트 포맷 · 나머지 코드 · broken 픽스처 좌표 확인을
맡습니다. 규칙 파일(`validate/rules/*.js`)은 S3 이후의 코드에만 생깁니다.

## 4. 2패스 조립

```
pass 1   모든 시트의 헤더를 읽는다 (enum 정의 시트 포함)
         ↓ 이 시점에 "Item.id 는 int" 를 알게 된다
pass 2   데이터 행을 캐스팅한다
```

`notation.md` §4.3 이 "`ref` 의 C# 타입은 대상 필드의 타입을 그대로 따른다" 고
정했으므로, `ref:Item.id[]` 열의 값을 캐스팅하려면 다른 시트의 헤더가 먼저 필요합니다.
한 패스로는 불가능합니다.

### 4.1 시트 분류

| 조건 | 처리 |
|---|---|
| 시트명이 `#` 또는 `_` 로 시작 | 무시. IR 에 넣지 않는다 |
| 시트명이 `enum.` 으로 시작 | enum 정의 시트 (§4.2) |
| 그 외 | 데이터 시트 |

무시 규칙을 먼저 적용합니다. `_enum.Old` 는 무시 시트입니다.

`source.sheetCount` 는 무시 시트를 포함한 워크북 전체 시트 수입니다. 원본 파일에
대한 정보이므로 도구의 필터링 결과를 반영하지 않습니다.

### 4.2 enum 정의 시트

필드명 행에서 `name` · `value` · `comment` 열을 찾습니다(§1.3). `name` 열이 없으면
`E010` 이고 그 시트는 IR 에 넣지 않습니다.

`value` 생략 시 이전 멤버 + 1, 첫 멤버면 0 입니다(`spec.md` §3.3).
자동 증가는 **직전 멤버의 확정된 값** 기준입니다 — 명시값 `10` 다음의 생략은 `11`
입니다.

### 4.3 빈 행

데이터 영역에서 모든 셀이 비어 있는 행은 건너뜁니다. 사양에 없는 판단입니다.
엑셀 시트 끝에 서식만 남은 빈 행이 흔하고, 이를 데이터로 읽으면 기본키가 비어
`E003` 이 무더기로 나옵니다.

일부 셀만 빈 행은 건너뛰지 않습니다. 그건 실제 누락이므로 `E003` 이 맞습니다.

## 5. 셀을 문자열로 읽는 규칙

`notation.md` §5.1 이 "모든 셀은 문자열로 읽는다" 고 정했습니다. SheetJS 에서
그것을 얻는 방법에 판단이 필요합니다.

### 5.1 `sheet_to_json` 을 쓰지 않는다

`XLSX.utils.sheet_to_json` 은 뒤쪽 빈 열을 잘라내 행마다 배열 길이가 달라질 수
있습니다. 열 인덱스가 밀리면 오류 좌표가 어긋나고, 좌표가 어긋나면 이 도구의 가치가
사라집니다. `!ref` 범위를 직접 순회합니다.

### 5.2 서식된 텍스트가 아니라 원시 값을 읽는다

셀의 `w`(formatted text)가 아니라 `v`(raw value)를 씁니다. 천 단위 서식이 걸린
`1000` 셀은 `w` 로 읽으면 `"1,000"` 이 되고, 이는 배열 구분자와 충돌합니다
(`notation.md` §3).

| SheetJS `t` | 문자열 변환 |
|---|---|
| `s` 문자열 | 그대로 |
| `n` 숫자 | `String(v)` — 서식 무시 |
| `b` 불리언 | `'TRUE'` / `'FALSE'` — §3.1 의 허용 표기 |
| `e` 오류 | `w` (`#REF!` 등). 캐스팅에서 `E006` 이 되어 좌표와 함께 보고된다 |
| 없음 · `z` | `''` |

### 5.3 `cellDates: false`

`datetime` 은 시리얼 넘버로 받아야 `notation.md` §3.2 의 "시리얼 60 이하 거부" 를
적용할 수 있습니다. SheetJS 가 `Date` 로 바꿔버리면 1900 윤년 버그 구간을 구분할
수 없습니다.

### 5.4 공백 제거는 리더가 하지 않는다

`workbook-reader` 는 원본을 그대로 문자열로 옮기는 단일 책임만 갖습니다.
앞뒤 공백 제거(`notation.md` §5.1)는 값 해석 규칙이므로 `value-parser` 와
`header-parser` 가 각자 진입 시점에 합니다.

이 구분이 필요한 이유는 배열입니다. `"  a  ",b` 에서 따옴표 안의 공백은 보존해야
하는데, 리더가 셀 전체를 trim 하면 어디까지가 따옴표 안인지 알 수 없습니다.

### 5.5 CSV

`spec.md` §3.5 대로 시트 하나짜리 워크북으로 취급하고 시트명은 파일명에서 확장자를
뗀 것으로 합니다. SheetJS 의 CSV 파서를 그대로 씁니다 — 따옴표 처리 규칙을 직접
구현할 이유가 없습니다.

## 6. 값 캐스팅

`notation.md` §3 · §5 를 그대로 구현합니다. 문서가 정하지 않은 것만 적습니다.

### 6.1 datetime 출력 형식

IR 에는 **UTC ISO 8601 문자열**로 넣습니다. `Date` 객체는 골든 JSON 비교가 안 되고,
시리얼 넘버 그대로 두면 에미터가 다시 해석해야 해 §4.1 을 어깁니다.

시리얼 → UTC 변환의 기준점은 `1899-12-30` 입니다. 시리얼 61 이 `1900-03-01` 이
되는지 테스트로 고정합니다. 60 이하는 `E006` 입니다.

`new Date(밀리초)` 는 인자가 있으므로 결정적입니다. CLAUDE.md 규칙 6 이 금지하는
것은 현재 시각을 읽는 `Date.now()` · `new Date()` 입니다.

### 6.2 ref 값의 캐스팅

대상 필드의 TypeNode 로 재귀 캐스팅합니다. 대상이 없으면 `E008` 이 헤더 단계에서
나오고, 그 열의 값은 문자열 그대로 둡니다. 값을 버리지 않는 이유는 미리보기에서
사용자가 무엇을 썼는지 봐야 하기 때문입니다.

참조는 **한 단계만** 따라갑니다. 대상 필드의 타입이 다시 `ref` 이면 거기서 멈추고
값을 문자열로 둡니다. `notation.md` §4.3 이 순환 참조를 허용하므로, 끝까지 따라가는
구현은 `A.x → B.y → A.x` 에서 멈추지 않습니다. 실제로 참조의 참조가 필요한 시트가
나오면 그때 방문 집합을 들고 다니는 해석기를 넣습니다.

### 6.3 enum · loc

값을 문자열 그대로 IR 에 넣습니다. 멤버 존재 확인(`E009`)과 키 형식 확인(`W106`)은
IR 이 만들어진 뒤에도 할 수 있으므로 S3 소관입니다.

## 7. IR 의 범위 — `identifier` 와 `className` 은 아직 없다

`spec.md` §4 의 IR 은 `identifier`(필드) 와 `className`(시트) 을 갖습니다. 둘 다
`emit/csharp/naming.js` 의 결과이고, 그 파일은 S5 입니다.

**S2 의 IR 은 `name` 만 채웁니다.** `irVersion` 은 1 이고, S5 에서 두 필드가 추가될
때 2 로 올리며 골든을 `chore(golden)` 커밋으로 갱신합니다.

naming 을 S2 로 당기는 대안도 검토했습니다. 골든 IR 이 한 번 만들어지면 안 흔들린다는
장점이 있지만, C# 예약어 목록과 `E007` · `E011` · `E015` · `W105` 가 함께 딸려
들어와 "한 세션 한 관심사"(CLAUDE.md)를 어깁니다. 버전 올림은 §4.1 이 이미 준비해 둔
정상 경로이므로 그쪽을 씁니다.

## 8. 테스트

```
test/support/golden.mjs        assertGolden(name, text) — UPDATE_GOLDEN=1 존중
test/golden/basic.ir.json      이번에 생기는 첫 골든 파일
test/a1.test.mjs
test/workbook-reader.test.mjs
test/header-parser.test.mjs
test/value-parser.test.mjs
test/build-ir.test.mjs
```

개발가이드 §2 는 `parser.test.mjs` 하나로 적었지만 모듈별로 나눕니다. 다섯 모듈을 한
파일에 넣으면 실패했을 때 원인 모듈을 찾는 비용이 커집니다.

### 8.1 반드시 들어가는 케이스

- **빈 셀 4종** — `undefined` · `''` · `'   '` · 셀 없음이 모두 같게 취급되는가
- **빈 값의 타입별 결과** — `T?` → `null`, `T[]` → `[]`, `T[]?` → `null`, 그 외 `E003`
- **배열 따옴표** — `"a,b",c` · `"say ""hi"""` · `2001,,2003` → `E006`
- **bool 10종** — `TRUE` `true` `1` `Y` `O` / `FALSE` `false` `0` `N` `X`, 대소문자 무시
- **datetime 경계** — 시리얼 60 거부 · 61 = `1900-03-01` · ISO 문자열 · `2026/07/29` 거부
- **`long` 안전 범위 경계** — `9007199254740991` 통과, `9007199254740993` → `E006`
- **좌표** — 모든 진단이 `Monster!D17` 형태의 좌표를 갖는가 (좌표 없는 진단은 실패)
- **결정성** — 같은 워크북을 두 번 읽어 IR JSON 이 바이트 단위로 같은가

### 8.2 골든 파일의 최초 생성

`test/golden/basic.ir.json` 은 아직 없습니다. `UPDATE_GOLDEN=1` 로 만든 뒤 내용을
