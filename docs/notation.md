# 타입 표기 스펙 (notation)

> **초안 — 검토 전입니다.** 승인 전에는 이 문서를 근거로 구현을 시작하지 마십시오.
> 실제 데이터시트 없이 작성했으므로, 시트 관습과 충돌하는 부분이 나오면 이 문서를 고칩니다.

데이터시트의 타입 행에 쓰는 표기법입니다. `game-sheet-exporter` 구현에 의존하지 않도록
자족적으로 씁니다.

---

## 1. 왜 표기법이 필요한가

엑셀 셀에는 타입이 없습니다. `1001`은 숫자일 수도 문자열일 수도 있고, `2001,2002`는
쉼표가 들어간 문자열일 수도 두 개의 정수 배열일 수도 있습니다. 사람은 열 이름을 보고
짐작하지만 코드 생성기는 짐작하면 안 됩니다.

이 표기법은 **시트 안에 타입을 명시**해서 그 짐작을 없앱니다. 타입 행이 곧 스키마입니다.

---

## 2. 문법

```ebnf
type        = base , { suffix } ;
suffix      = "?" | "[]" ;
base        = scalar | enum-ref | sheet-ref | loc ;

scalar      = "int" | "long" | "float" | "double" | "bool" | "string" | "datetime" ;
enum-ref    = "enum" , ":" , identifier ;
sheet-ref   = "ref"  , ":" , identifier , "." , identifier ;
loc         = "loc" ;

identifier  = letter , { letter | digit | "_" } ;
```

파싱은 **재귀 하강**으로 합니다. 정규식 하나로 처리하지 마십시오 — 접미사가 여러 개
붙을 수 있고, 중첩 표기가 나중에 추가됩니다.

**대소문자는 구분**합니다. `Int`, `INT`는 오류입니다. 디자이너가 자유롭게 쓰기
시작하면 표기가 흔들리고, 흔들린 표기는 오탈자를 숨깁니다.

**토큰 사이의 공백은 무시**합니다. `ref : Item . id [ ] ?` 는 `ref:Item.id[]?` 와 같습니다.
다만 **식별자 안에는 공백을 넣을 수 없습니다**. `enum:Item Type` 은 오류이며,
조용히 `enum:ItemType` 으로 합쳐지지 않습니다. 표기 전체에서 공백을 지워버리면
디자이너의 오타가 유효한 표기로 둔갑합니다.

### 2.1 접미사 결합 순서

접미사는 **왼쪽부터 순서대로** 적용합니다.

| 표기 | 의미 | C# |
|---|---|---|
| `int` | 정수 | `int` |
| `int?` | 빈 셀 허용 정수 | `int?` |
| `int[]` | 정수 배열 | `int[]` |
| `int[]?` | 배열 전체가 없을 수 있음 | `int[]` (빈 셀 → `null`) |
| `int?[]` | 배열이되 원소가 없을 수 있음 | `int?[]` |

`int[]?`와 `int?[]`는 다릅니다. 순서를 뒤집으면 다른 타입이 됩니다.

### 2.2 중첩 제한

파서는 임의 깊이를 파싱합니다. 다만 **v1 에미터는 배열 깊이 1까지만** 지원하며,
`int[][]` 같은 표기는 파싱은 되지만 내보내기 단계에서 `E013`으로 거부됩니다.

파서와 에미터의 지원 범위를 일부러 다르게 둡니다. 나중에 깊이를 늘릴 때 파서를
다시 건드리지 않기 위해서입니다.

## 3. 스칼라 타입

| 표기 | C# | 허용 입력 | 비고 |
|---|---|---|---|
| `int` | `int` | `-?[0-9]+` | 32비트. 범위 초과는 `E006` |
| `long` | `long` | `-?[0-9]+` | 64비트 |
| `float` | `float` | `-?[0-9]+(\.[0-9]+)?` | 지수 표기 `1e5` 허용 |
| `double` | `double` | 위와 같음 | |
| `bool` | `bool` | 아래 표 참조 | |
| `string` | `string` | 임의 문자열 | 앞뒤 공백은 제거됨 |
| `datetime` | `System.DateTime` | 엑셀 날짜 셀 또는 ISO 8601 | 아래 3.2 참조 |

천 단위 구분 쉼표(`1,000`)는 **허용하지 않습니다**. 배열 구분자와 충돌합니다.
엑셀에서 쉼표는 표시 서식일 뿐이므로 셀의 실제 값은 `1000`으로 읽힙니다.

### 3.1 bool

| 참 | 거짓 |
|---|---|
| `TRUE` `true` `1` `Y` `O` | `FALSE` `false` `0` `N` `X` |

`TRUE`/`FALSE`는 엑셀 체크박스가 내놓는 값이고, `O`/`X`와 `Y`/`N`은 한국어권 게임
데이터시트에서 흔히 쓰입니다. 대소문자는 구분하지 않습니다. 이 목록에 없는 값은 `E006`입니다.

빈 셀은 거짓이 **아닙니다**. `bool`은 명시를 요구하고, 비워두려면 `bool?`을 씁니다.

### 3.2 datetime

엑셀 날짜는 셀에 시리얼 넘버로 들어옵니다 (1900-01-01 = 1). 1900년을 윤년으로 잘못
처리하는 엑셀의 호환성 버그가 있어, **시리얼 60 이하는 `E006`으로 거부**합니다.
1900년 2월 이전 날짜를 게임 데이터에 쓸 일은 없고, 그 구간에서 조용히 하루가
어긋나는 것보다 거부하는 편이 낫습니다.

문자열로 들어온 경우 ISO 8601(`2026-07-29` 또는 `2026-07-29T12:00:00Z`)만 받습니다.
`2026/07/29`나 `26.7.29` 같은 지역 서식은 해석이 갈리므로 거부합니다.

출력은 항상 UTC ISO 8601 문자열입니다.

## 4. 접두 표기

### 4.1 `loc` — 로컬라이즈 키 참조

셀에는 번역문이 아니라 **키만** 들어갑니다.

```
name
loc
이름
MON_SLIME
```

C# 타입은 `string`입니다. 검증은 두 단계입니다.

1. 키 형식 확인 — `[A-Z][A-Z0-9_]*` (대문자·숫자·밑줄). 위반 시 `W106`
2. 키 존재 확인 — 로컬라이즈 테이블이 함께 주어진 경우에만. 없는 키는 `E014`

로컬라이즈 테이블이 없으면 2번은 건너뜁니다. 번역 작업이 데이터 작업보다 늦게
따라오는 게 보통이므로, 키가 아직 없다고 내보내기를 막지는 않습니다.

> **대안 검토** — `name_ko` / `name_en` 처럼 언어별 열을 두는 방식도 있습니다.
> 시트만 보면 내용을 알 수 있어 편하지만, 언어가 늘 때마다 모든 시트의 열이 늘고
> 번역 담당자가 게임 데이터 시트를 직접 건드려야 합니다. 키 참조 방식을 택합니다.

### 4.2 `enum:<Name>` — 열거형

셀에는 멤버 이름이 들어갑니다.

```
grade
enum:Grade
등급
Normal
```

`Grade`는 **enum 정의 시트**에 있어야 합니다 (spec.md §3.3). 정의에 없는 값은 `E009`,
정의 시트 자체가 없으면 `E008`입니다.

값에서 자동으로 enum을 수집하지 **않습니다**. 오타 하나가 조용히 새 멤버가 되어
생성 코드에 섞이는 것을 막기 위해서입니다.

### 4.3 `ref:<Sheet>.<Field>` — 참조 무결성

```
drop_ids
ref:Item.id[]
드랍
2001,2002
```

대상 시트의 대상 필드에 그 값이 실제로 존재해야 합니다. 없으면 `E004`,
대상 시트나 필드 자체가 없으면 `E008`입니다.

C# 타입은 **대상 필드의 타입을 그대로** 따릅니다. `Item.id`가 `int`이므로
`ref:Item.id[]`는 `int[]`가 됩니다.

참조 대상 필드는 시트 안에서 유일해야 합니다. 중복 값이 있으면 `E012`입니다.
참조 대상이 아닌 필드의 중복은 문제 삼지 않습니다.

순환 참조(`A.x → B.y → A.z`)는 값 수준 참조일 뿐 타입 재귀가 아니므로 허용합니다.

## 5. 셀 값 규칙

### 5.1 모든 셀은 문자열로 읽는다

엑셀에서 읽은 값은 타입 캐스팅 이전에 전부 문자열입니다. 캐스팅은 타입 표기가
지시하는 대로만 일어납니다. "숫자처럼 생겼으니 숫자"는 없습니다.

앞뒤 공백은 제거합니다. 문자열 안쪽 공백은 보존합니다.

### 5.2 빈 셀

셀이 없는 경우(`undefined`), 빈 문자열(`""`), 공백 문자만 있는 경우를 **모두 동일하게**
"빈 값"으로 취급합니다. 셋을 구분하는 순간 엑셀 편집 이력에 따라 결과가 달라집니다.

| 타입 | 빈 셀의 결과 |
|---|---|
| `T?` | `null` |
| `T[]` | 빈 배열 `[]` |
| `T[]?` | `null` |
| 그 외 | `E003` (필수 값 누락) |

기본값을 조용히 채우지 않습니다. 비어 있는 `int` 열이 `0`으로 나가면 밸런스 데이터에서
가장 찾기 어려운 종류의 버그가 됩니다. 비워도 되는 열이면 `?`를 붙이는 것이 의도의 표현입니다.

### 5.3 배열

셀 안에서 **쉼표**로 구분합니다. 구분자는 설정으로 바꿀 수 있습니다.

```
2001,2002,2003     → [2001, 2002, 2003]
2001, 2002         → [2001, 2002]      (원소 앞뒤 공백 제거)
                   → []                (빈 셀)
2001,,2003         → E006              (빈 원소 거부)
```

`string[]`의 원소에 구분자를 넣어야 하면 큰따옴표로 감쌉니다. CSV와 같은 규칙입니다.

```
"a,b",c            → ["a,b", "c"]
"say ""hi"""       → ['say "hi"']
```

빈 원소를 거부하는 이유는 `2001,,2003`이 대개 오타이기 때문입니다. 의도적으로
빈 원소가 필요하면 `string?[]`처럼 원소 nullable을 명시합니다.

## 6. 파싱 예시

| 표기 | 결과 TypeNode |
|---|---|
| `int` | `{ kind: 'scalar', name: 'int' }` |
| `int?` | `{ kind: 'nullable', of: scalar(int) }` |
| `int[]` | `{ kind: 'array', of: scalar(int) }` |
| `int[]?` | `{ kind: 'nullable', of: array(scalar(int)) }` |
| `int?[]` | `{ kind: 'array', of: nullable(scalar(int)) }` |
| `loc` | `{ kind: 'loc' }` |
| `enum:Grade` | `{ kind: 'enum', name: 'Grade' }` |
| `enum:Grade[]` | `{ kind: 'array', of: enum(Grade) }` |
| `ref:Item.id` | `{ kind: 'ref', sheet: 'Item', field: 'id' }` |
| `ref:Item.id[]` | `{ kind: 'array', of: ref(Item.id) }` |
| `ref:Item.id[]?` | `{ kind: 'nullable', of: array(ref(Item.id)) }` |

## 7. 거부 사례

전부 `E005`(표기 파싱 실패)입니다.

| 입력 | 이유 |
|---|---|
| `` (빈 문자열) | 타입 표기 없음 — 단, 필드명도 비었으면 그 열은 무시 대상이므로 `E002` 아님 |
| `Int` | 대소문자 구분 |
| `integer` | 알 수 없는 스칼라 |
| `enum` | 이름 누락 |
| `enum:` | 이름 누락 |
| `enum:1Grade` | 식별자가 숫자로 시작 |
| `ref:Item` | 필드 누락 |
| `ref:Item.` | 필드 누락 |
| `ref:.id` | 시트 누락 |
| `int[` | 닫히지 않은 접미사 |
| `int]` | 여는 괄호 없음 |
| `int??` | 중복 nullable — 의미가 없으므로 오타로 본다 |
| `?int` | 접미사가 앞에 옴 |
| `loc:Name` | `loc`은 인자를 받지 않음 |
| `int x` | 표기 뒤에 남은 문자 |
| `enum:Grade Y` | 표기 뒤에 남은 문자 — 식별자에 공백을 허용하지 않으므로 `GradeY` 로 합쳐지지 않는다 |
| `ref:Item.id.extra` | 표기 뒤에 남은 문자 |
| `int[]]` | `[` 없이 `]` |

문자열이 아닌 입력(`null`, 숫자, 객체)도 `E005`입니다.

`int??`를 굳이 거부하는 이유는, 허용하면 `int??`와 `int?`가 같은 타입이 되어
표기가 두 가지로 갈리기 때문입니다. 표기가 갈리면 시트를 읽는 사람이 차이를 찾습니다.

## 8. 확장 지점

지금 넣지 않았지만 문법이 자리를 비워둔 것들입니다.

- **기본값** — `int = 0`. 빈 셀을 에러 대신 기본값으로 채웁니다. 편하지만
  §5.2에서 경계한 "조용한 0"을 다시 불러들이므로 실제 필요가 확인된 뒤에 넣습니다.
- **범위 제약** — `int(1..99)`. 검증기가 할 일을 타입 표기로 옮기는 것이라 신중해야 합니다.
- **중첩 struct** — `struct:Reward`. 한 열에 복합 값을 넣는 표기.
- **딕셔너리** — `map:string,int`.
