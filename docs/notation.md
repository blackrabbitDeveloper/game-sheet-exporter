# 타입 표기 스펙 (notation)

> **경고 — 이 문서는 아직 작성되지 않았습니다.**
>
> `src/core/parser/type-notation.js` 구현은 이 문서가 채워진 뒤에 시작합니다.

## 왜 비어 있는가

[spec.md](./spec.md)와 같은 이유입니다. 원본 기획서가 저장소에 없습니다.

타입 표기법은 이 도구의 입력 계약 전체를 정의합니다. 추측으로 만든 문법은 실제
데이터시트를 만나는 순간 무너지고, 그 시점의 재작업 비용이 이 프로젝트에서 가장 큽니다.

## 이 문서가 정해야 할 것

- **스칼라 타입 목록** — `int` `long` `float` `bool` `string` `datetime` 등 정확한 집합
- **접미사 의미와 결합 순서** — `?`(nullable), `[]`(array), 그리고 둘이 겹칠 때 (`int[]?` vs `int?[]`)
- **접두 표기** — `enum:<Name>`, `ref:<Sheet>.<Field>`, `loc`
- **중첩 허용 범위** — `ref:Item.id[]`처럼 접두 표기에 접미사가 붙는 규칙, 중첩 깊이 한계
- **구분자** — 배열 셀 내부 구분자(예: `2001,2002`), 이스케이프 규칙
- **대소문자 규칙** — 표기가 대소문자를 구분하는지
- **빈 셀 처리** — `undefined` / 빈 문자열 / 공백만 있는 셀을 어떤 값으로 볼지
- **거부 사례** — 파싱 실패로 `E005`를 내야 하는 입력의 예시

## 구현 시 제약 (개발가이드 §4.1에서 확정)

중첩 표기가 나중에 추가되므로, 정규식 하나로 처리하지 말고 접미사(`?`, `[]`)를
벗겨내며 **재귀 하강**으로 파싱합니다.

## 향후 계획

이 문서는 도구와 독립적으로 공개할 수 있도록 자족적으로 작성합니다.
`game-sheet-exporter` 구현 세부에 의존하는 서술을 넣지 않습니다.
